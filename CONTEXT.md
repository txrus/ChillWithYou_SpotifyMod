# CONTEXT.md — domain glossary

Terms with a fixed meaning in this codebase. Use these words exactly; don't drift to synonyms.

- **Envelope** — everything wrapped around a Spotify HTTP request: token attach, transient-auth retry, 429 reporting, error logging. Owned by `SpotifyGateway`; its pure decisions (what to do with a given response) live in `SpotifyGatewayPolicy`.
- **Optimistic command** — apply the expected state to the panel immediately, send the command, reconcile after. Two reconcile policies, tabled in `RunOptimistic` (SpotifyButtonInjector): *revert on failure* (shuffle, repeat — buttons that display state) vs *let the poll correct* (volume, seek — dragged values where a bounce-back is worse than 6 s of drift).
- **The bench** — the xUnit test project (`tests/NowPlayingSession.Tests`), which link-compiles pure-logic files only (no UnityEngine, no Newtonsoft). "On the bench" = testable without launching the game. Benched modules: `NowPlayingSession`, `PanelViewModel`, `RefreshCoordinator`, `SpotifyModels`, `SpotifyGatewayPolicy`.
- **Queue window** — the up-to-21-track slice of the playing context shown in the panel (`/me/player/queue` ceiling: current + 20, no pagination). When the playing song falls off the shown rows within the same context, the window *slides*: rows are refetched, the header stays. All rows show in one scrollable list — client-side pagination (splitting this into pages) was tried and pulled back out after not working correctly in game; don't reintroduce it without knowing what specifically failed.
- **Playlist listing vs. live queue** — `/playlists/{id}` returns a playlist's fixed, saved track order and has no relationship to playback state; it does not reflect shuffle. `/me/player/queue` reflects whatever is actually about to play, shuffled or not. A playlist context normally sources its on-screen queue from the former (one call gets name + cover + tracks); when shuffle is on, tracks are sourced from the latter instead so the on-screen order matches reality, while the header still uses the playlist's real name and cover from the same listing call.
- **Context** (Spotify sense) — what playback walks through: a playlist, album, or artist URI, or the user's saved-tracks collection (`spotify:user:*:collection`). The collection context is *view-only* — Spotify accepts no `context_uri` for it and the direct `/me/tracks` listing endpoint returns 403 in development mode, so Liked Songs is only ever shown via the queue window (labeled "LIKED SONGS"), and its rows aren't clickable.
- **Development-mode 403** — Spotify blocks the `/me/tracks` endpoint family (get/save/remove saved tracks) for apps in development mode, even with the correct scopes granted. Confirmed dead end, not a bug to retry: the save-song and direct Liked Songs features were removed rather than left half-working. See `docs/adr/0001-drop-library-integration.md`.
